# PRD: 나만의 프롬프트 관리 프로그램 (Prompt Manager)

> 근거 문서: [project.md](../project.md)

## 1. 개요

- **목적:** 흩어진 프롬프트를 터미널 한 곳에서 추가·조회·검색·즐겨찾기로 관리한다.
- **학습 목표:** Python 기초 문법(변수·조건·반복·함수·리스트·딕셔너리)과 Git 워크플로(`init`, `add`, `commit`, `push`, `pull`, `checkout`, `clone`, `merge`)를 체득한다.
- **형태:** Python 3.10+ 콘솔 프로그램 1개(외부 라이브러리 없음) + GitHub 저장소 1개

## 2. 범위

| 구분 | 내용 |
|---|---|
| 필수(In) | 메뉴, 기본 데이터, 추가, 목록, 카테고리별 조회, 검색, 상세 보기, 즐겨찾기 토글/목록, README |
| 선택(보너스) | JSON 저장/불러오기, Markdown 내보내기, 수정/삭제, 조회수·Top 목록 — 필수 완료 후 별도 단계 |
| 제외(Out) | 필수 범위의 파일 저장(종료 시 초기화), GUI, 외부 라이브러리 |

## 3. 메뉴 구성

```text
=== 나만의 프롬프트 관리 ===
1. 프롬프트 추가
2. 프롬프트 목록
3. 카테고리별 조회
4. 프롬프트 검색
5. 프롬프트 상세 보기
6. 즐겨찾기 관리 (추가/해제)
7. 즐겨찾기 목록
0. 종료
```

- 각 기능 수행 후 항상 메뉴로 복귀한다.
- 잘못된 번호·숫자가 아닌 값 입력 시 "올바른 번호를 입력하세요" 안내 후 메뉴를 다시 출력한다.
- `0` 입력 시 종료 메시지를 출력하고 종료한다. `Ctrl+C` 입력 시에도 오류 없이 정상 종료한다.

## 4. 기능 요구사항

| ID | 기능 | 상세 동작 | 예외 처리 |
|---|---|---|---|
| F1 | 기본 데이터 | 시작 시 이전 미션 프롬프트 3개 이상(목표 5개) 등록 | – |
| F2 | 추가 | 제목 → 내용 → 카테고리(1~6 선택, 7 "직접 입력") 순으로 입력. 직접 입력한 카테고리는 카테고리 목록에 추가되어 조회에도 노출. `favorite=False`로 저장 후 완료 메시지 | 빈 값·공백만 입력 시 재입력, 잘못된 카테고리 번호 시 재입력 |
| F3 | 목록 **(브랜치 작업)** | `번호. [카테고리] 제목 ⭐` 형식으로 전체 출력 + "총 N개의 프롬프트" | 0개면 "등록된 프롬프트가 없습니다" |
| F4 | 카테고리별 조회 | 카테고리 목록 출력 → 선택 → 해당 카테고리 프롬프트만 출력 + "총 N개" | 해당 카테고리에 없으면 안내, 잘못된 번호 시 재입력 |
| F5 | 검색 | 키워드가 제목 또는 내용에 포함된 프롬프트 검색(대소문자 무시) → 결과 목록 + "N개의 프롬프트를 찾았습니다" | 빈 키워드 시 재입력, 결과 없으면 안내 |
| F6 | 상세 보기 | 번호 입력 → 구분선과 함께 제목, 카테고리, 즐겨찾기 여부, 전체 내용 출력 | 범위 밖·숫자가 아닌 값이면 안내 후 메뉴 복귀 |
| F7 | 즐겨찾기 관리 | 번호 입력 → 즐겨찾기 상태 토글 → "'제목' 프롬프트를 즐겨찾기에 추가/해제했습니다!" | F6과 동일 |
| F8 | 즐겨찾기 목록 | `favorite=True`인 항목만 출력 + "총 N개의 즐겨찾기" | 0개면 안내 |

**번호 정책:** 카테고리별 조회·검색·즐겨찾기 목록에서도 **전체 목록 기준 번호**를 표시한다. 결과에서 본 번호를 그대로 상세 보기·즐겨찾기 관리에 입력할 수 있게 하기 위함이다. (project.md의 출력 예시는 참고용)

## 5. 데이터 설계

```python
CATEGORIES = ["텍스트 생성", "이미지 생성", "영상 생성", "페르소나", "자동화", "기타"]

prompts = [  # list[dict]
    {"title": str, "content": str, "category": str, "favorite": bool},
]
```

- 기본 데이터는 상수 `DEFAULT_PROMPTS`로 두고, 프로그램 시작 시 복사해 `prompts`를 만든다.
- 기본 데이터 후보(가칭): 블로그 글 작성 도우미(텍스트 생성), 제품 썸네일 생성(이미지 생성), 광고 스크립트 작성(영상 생성), IT 컨설턴트 페르소나(페르소나), 뉴스 요약 자동화(자동화)
  - **구현 전에 실제 이전 미션에서 작성한 프롬프트로 교체한다.**

## 6. 코드 구조

`prompt_manager.py` 단일 파일, 기능별 함수로 분리한다.

| 분류 | 함수 |

## 7. Git 전략

> GitHub 새 저장소 생성, `git init`, 10개 이상의 커밋, 브랜치 생성·병합 수행 절차는 [CLI_실행_가이드.md](CLI_실행_가이드.md)로 대신한다.

### 저장소

- GitHub에 새 공개 저장소(예: `prompt-manager`)를 생성한다. 기본 브랜치는 `main`.

### 브랜치

- 목록 기능(F3)을 `feature/prompt-list` 브랜치에서 작업한다.
- 병합은 `git merge --no-ff feature/prompt-list`로 수행하여 `git log --graph`에 병합 기록이 남도록 한다.

### 커밋 계획 (13개, 기능 단위)

1. `chore: 프로젝트 초기화 (.gitignore, README 제목)`
2. `feat: 메뉴 출력 및 메인 루프, 종료 기능`
3. `feat: 잘못된 메뉴 입력 처리`
4. `feat: 이전 미션 프롬프트 기본 데이터 등록`
5. `feat: 입력 검증 헬퍼 함수 추가`
6. `feat: 프롬프트 추가 기능`
7. `feat: 프롬프트 목록 기능` ← `feature/prompt-list` 브랜치
8. `Merge branch 'feature/prompt-list'`
9. `feat: 카테고리별 조회 기능`
10. `feat: 프롬프트 검색 기능`
11. `feat: 프롬프트 상세 보기 기능`
12. `feat: 즐겨찾기 추가/해제 및 목록 기능`
13. `docs: README 기능 목록·실행 방법·카테고리 설명 작성`

### 명령어 사용 계획

| 명령어 | 사용 시점 |
|---|---|
| `init` | 로컬 저장소 생성 |

## 10. 수용 기준 (테스트 시나리오)

| # | 입력 | 기대 결과 |
|---|---|---|

| T6 | 검색 "블로그" / "없는단어" | 결과 목록 / 결과 없음 안내 |
| T7 | 상세 보기 `1` / `999` | 전체 내용 출력 / 오류 안내 |
| T8 | 즐겨찾기 관리에 `2`를 두 번 입력 | 추가 메시지 → 해제 메시지 |
| T9 | 즐겨찾기 목록 | ⭐ 항목만 출력 |
| T10 | `0` 입력 | 정상 종료 |
