## 1. 개요

### 1.1 배경
구글 계정에는 내가 언제 무엇을 검색하고 어떤 YouTube 영상을 봤는지가 초 단위 타임스탬프로 남아 있습니다.
이 기록은 "나의 관심사와 생활 리듬"을 보여 주는 개인 시계열 데이터입니다.
Google Takeout으로 받은 데이터를 정제하고 시각화하면, 그래프 너머의 의미를 해석해 볼 수 있습니다.

### 1.2 목표
1. Google Takeout의 **Google 검색 기록**과 **YouTube 시청·검색 기록**을 파싱해 정제된 시계열 데이터셋을 만든다.
2. 시계열 분석 기법(이동평균, 변화율, 구간 통계, 요일·시간대 집계 등)으로 패턴을 찾는다.
3. 분석 결과를 `REPORT.md`로 정리한다. 인사이트는 3개 이상이며, 관찰(Fact)과 해석(가설)을 구분한다.
4. (보너스) 기간·조건을 바꿔 가며 탐색할 수 있는 웹 대시보드를 만들어 배포한다.
5. (보너스) 시계열 분해(STL)와 베이스라인 예측을 수행한다.
6. 계정에 YouTube 채널(브랜드 계정)이 여러 개여도, 내 채널(프로필)별로 시청 패턴을 나누고 비교할 수 있게 한다.
7. 모든 개발과 분석은 프로젝트 전용 Python 가상환경(`.venv`)에서 진행해 재현성을 보장한다.
8. Chrome 방문 기록을 **도메인 단위**로 분석해, 검색·YouTube와 합친 하루 전체 디지털 활동과 자주 가는 사이트의 변화를 본다.

### 1.3 성공 기준
| 항목 | 기준 |
|------|------|
| 데이터 규모 | 일 단위 집계 기준 100일 이상, 이벤트 기준 수천 건 이상 |
| 분석 질문 | 3개 이상 정의, 각 질문에 그래프 근거로 답변 |

## 2. 범위

### 2.1 포함 (In Scope)
- Google Takeout 데이터 다운로드 가이드 문서화 (개인 계정 + 브랜드 계정별)
- 검색 기록과 YouTube 시청·검색 기록 파싱, 정제, 집계
- 내 채널(프로필)별 분리·비교 분석
- 분석 노트북(`analysis.ipynb`)과 리포트(`REPORT.md`)
- Streamlit 대시보드(파일 업로드 또는 샘플 데이터 모드)
- 시계열 분해(STL)와 단기 베이스라인 예측
- Python 가상환경 기반 개발 환경 구성과 문서화
- Chrome 방문 기록(도메인 단위) 파싱·집계와 검색·YouTube 통합 분석

### 2.2 제외 (Out of Scope)
- Google API(OAuth)를 이용한 실시간 데이터 수집. Takeout 수동 다운로드만 지원한다.
- 위치 기록, Gmail 등 다른 Takeout 서비스
- Google 검색·YouTube 검색 기록의 실제 데이터 분석 (1.4 참고. 파서·샘플 지원은 유지)
- Chrome 방문 기록의 URL 경로·쿼리와 페이지 제목 (저장하지 않음)
- 로컬 PC의 Chrome 기록 파일(SQLite) 직접 읽기. Takeout만 지원한다
- 업로드 데이터의 서버 저장, 회원 기능
- 영상 메타데이터(카테고리, 길이) 외부 API 조회. 향후 확장 항목으로 둔다.

## 3. 사용자 및 시나리오

### 3.1 대상 사용자
- **1차**: 본인(분석가). 내 디지털 습관을 데이터로 확인하고 싶은 사람
- **2차**: 대시보드 방문자(평가자, 동료). 샘플 데이터나 자기 Takeout 파일로 직접 탐색해 보는 사람

### 3.2 사용자 시나리오
1. 사용자가 Google Takeout에서 "내 활동"과 "YouTube 및 YouTube Music"을 **JSON 형식**으로 내보낸다. YouTube 채널이 여러 개라면 **계정 전환기에서 채널(브랜드 계정)마다 따로 내보낸다.** 개인 계정 내보내기에는 **Chrome** 방문 기록도 포함한다.
2. 받은 zip 파일(또는 JSON 파일)을 **하나 이상** 대시보드에 업로드한다. 앱은 파일마다 프로필(내 채널)을 자동으로 식별하고, 식별하지 못하면 사용자가 라벨을 입력한다.
3. 앱은 파일을 자동으로 찾아 파싱하고, 데이터 요약(기간, 건수, 결측·이상치, 프로필 목록)을 보여 준다.
4. 사용자는 기간, 서비스(검색/YouTube), 프로필, 집계 단위(일/주/월)를 바꿔 가며 추세와 패턴을 탐색한다.
5. 키워드·콘텐츠 채널 Top N과 요일×시간 히트맵으로 관심사와 생활 리듬을 확인한다.
6. 프로필이 2개 이상이면 채널 비교 탭에서 내 채널별 사용 패턴을 비교한다.

## 4. 데이터 명세

### 4.1 데이터 획득 절차 (README에 문서화)
1. https://takeout.google.com 에 접속해 "모두 선택 해제"를 누른다.
2. **내 활동(My Activity)**을 선택하고, 형식을 HTML에서 **JSON**으로 바꾼 뒤 "검색"과 "YouTube"만 포함한다. (개인 계정에서 1회)
3. **YouTube 및 YouTube Music**을 선택하고, 형식을 **JSON**으로 바꾼 뒤 **"기록"과 "채널"**을 포함한다.
   - "채널"을 포함하면 `channel.csv`가 들어 있어 프로필을 자동으로 식별할 수 있다.
4. 내보내기를 만들고 zip 파일을 다운로드한다.
5. **채널이 여러 개라면**: 페이지 오른쪽 위의 계정 전환기에서 브랜드 계정으로 바꾼 뒤 3~4단계를 채널마다 반복한다.
6. **Chrome 방문 기록** (개인 계정에서 1회, 둘 중 하나)
   - **내 활동 > Chrome** (JSON): "웹 및 앱 활동"에서 "Chrome 기록 포함"이 켜져 있어야 한다. 실제 내보내기로 구조를 확인한 형식이다.
   - **Chrome > 방문 기록** (BrowserHistory JSON): Chrome 동기화에서 "방문 기록" 동기화가 켜져 있어야 한다. 실제 파일로는 아직 확인하지 않았다.

> 폴더와 파일 이름은 계정 언어 설정에 따라 다르다(예: `My Activity/Search/MyActivity.json`, `YouTube 및 YouTube Music/기록/시청 기록.json`).
> 그래서 앱은 경로를 하드코딩하지 않고 zip 안의 JSON을 열어 `header`/`products` 필드로 데이터 종류를 판별한다.

### 4.2 원본 필드 (JSON 레코드 공통)
| 필드/파일 | 설명 | 사용 여부 |
|-----------|------|-----------|
| `header` | 서비스명 (`Search`, `YouTube` 등) | 서비스 분류 |
| `title` | 활동 설명 (예: "Searched for …", "… 을(를) 시청했습니다") | 활동 유형·키워드 추출 |
| `titleUrl` | 검색 URL(`q=` 파라미터) 또는 영상 URL | 검색어·영상 ID 추출 |
| `subtitles[].name` | 시청한 영상을 올린 채널명 | 콘텐츠 채널 집계 |
| `time` | ISO 8601 UTC 타임스탬프 | **시계열 인덱스** |
| `products` | 제품 목록 | 서비스 분류 보조 |
| `details[].name` | "From Google Ads" 등 | 광고 시청 제외 |
| `locationInfos` | 위치 정보 | **사용 안 함, 파싱 시 즉시 삭제** |
| `channel.csv` (YouTube 내보내기의 채널 폴더) | 내 채널 ID, 채널명 | **프로필 자동 식별** |

**Chrome 방문 기록 필드**
| 필드/파일 | 설명 | 사용 여부 |
|-----------|------|-----------|
| 내 활동 > Chrome: `products` | 항상 `["Chrome"]` | **웹 방문 판별** (`titleUrl`보다 먼저 확인) |
| 내 활동 > Chrome: `header` | 방문한 사이트 도메인 또는 `"Chrome"` | 사용 안 함 (도메인은 URL에서 직접 추출) |
| 내 활동 > Chrome: `title` | "<페이지 제목> 을(를) 방문했습니다." / "Chrome을 사용함" | 활동 판별만 하고 **제목은 버림** |
| 내 활동 > Chrome: `titleUrl` | 대부분 `https://www.google.com/url?q=<실제 URL>` 형태로 감싸져 있음 | **`q=`를 풀어 실제 도메인만 추출하고 원문은 버림** |
| BrowserHistory: `Browser History[]` | 최상위가 dict인 방문 기록 목록 | 웹 방문 이벤트 |
| BrowserHistory: `url`, `title` | 방문 URL, 페이지 제목 | 도메인만 추출, 제목은 버림 |
| BrowserHistory: `time_usec` | Unix epoch 마이크로초 (UTC) | 시계열 인덱스 |
| BrowserHistory: `page_transition` | LINK, TYPED, RELOAD 등 | 새로고침 제외, 직접 입력 비율 |

> 내 활동 > Chrome 형식에는 `page_transition`이 없다. 그래서 새로고침 제외와 직접 입력 비율은 BrowserHistory 형식에서만 가능하다.

> 주의: `subtitles[].name`은 시청한 영상을 **올린 채널**이다. 시청한 내 채널은 레코드에 기록되지 않는다.
> 그래서 어느 내 채널의 기록인지는 **내보내기(파일) 단위로만** 구분할 수 있다.

### 4.3 정제 후 스키마 (`events` 테이블)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| `ts_kst` | datetime | KST(Asia/Seoul)로 변환한 타임스탬프 |
| `profile` | category | 시청한 내 채널 라벨. `channel.csv`의 채널명 또는 사용자 입력. 검색 기록은 `"personal"` |
| `profile_id` | string | 내 채널 ID(식별 가능할 때만) |
| `service` | category | `search` / `yt_watch` / `yt_search` / `web_visit` |
| `activity` | category | `searched` / `visited` / `watched` / `typed`(주소 직접 입력, BrowserHistory만) |
| `text` | string | 검색어, 영상 제목, 웹 방문은 도메인 |
| `channel` | string | 시청한 영상을 올린 채널명 (용어: **"콘텐츠 채널"**, 없으면 null) |
| `video_id` | string | 영상 ID(없으면 null) |
| `domain` | string | 웹 방문 도메인(소문자, `www.` 제거). 다른 서비스는 null |

> 웹 방문 이벤트의 `profile`은 `"personal"`이다. Chrome 기록은 Chrome에 로그인한 개인 계정에 속한다.

> 용어 정의: **프로필(내 채널)** = 시청한 주체, **콘텐츠 채널** = 시청한 영상을 올린 쪽.
> 리포트와 대시보드 전체에서 이 두 용어를 구분해 쓴다.

### 4.4 정제 규칙
| 이슈 | 처리 기준 |
|------|-----------|
| 시간대 | UTC를 KST로 변환한 뒤 날짜·요일·시간을 파생한다 |
| 중복 레코드 | 내 활동 기록과 YouTube 기록에 같은 이벤트가 겹치면 (`profile`, `service`, `ts`, `text`) 기준으로 제거한다. **다른 프로필에서 같은 영상을 본 기록은 중복이 아니므로 남긴다** |
| 같은 내보내기 중복 업로드 | 같은 `profile_id`(또는 라벨)의 파일이 다시 들어오면 기존 데이터와 합친 뒤 중복을 제거하고 경고를 표시한다 |
| 프로필 식별 실패 | `channel.csv`가 없으면 `profile = "unknown-1"`처럼 임시 라벨을 붙이고 UI에서 이름을 바꿀 수 있게 한다 |
| 광고 시청 | `details`에 "Google Ads"가 있으면 제외한다 |
| 삭제·비공개 영상 | 제목이 URL뿐이고 채널이 없는 레코드는 `text="(삭제된 영상)"`으로 표시하고, 건수 집계에는 포함하되 콘텐츠 채널 분석에서는 제외한다 |
| 결측일 | 활동이 없는 날은 **0으로 채운다**(결측이 아니라 실제 0). 단, 기록이 7일 넘게 연속으로 0이면 "기록 중단 의심 구간"으로 따로 표시하고 리포트에서 언급한다 |
| 이상치 | 일별 건수가 `Q3 + 3×IQR`을 넘으면 이상치로 **표시만 하고 제거하지 않는다**. 사분위수는 활동이 있는 날만으로 계산한다(0이 대부분인 드문 시계열에서 활동일 전체가 이상치로 잡히는 것을 막기 위해). 몰아보기나 자동재생 같은 실제 행동일 수 있기 때문이다. 해석은 리포트에서 따로 다룬다 |
| 언어별 title | 영어·한국어 패턴을 정규식으로 모두 처리하고, 검색어는 가능하면 `titleUrl`의 `q=` 값을 우선 사용한다 |
| 웹 방문 판별 | `products`에 `Chrome`이 있으면 웹 방문으로 본다. `google.com/url` 래퍼가 있어도 검색의 "visited"로 분류하지 않는다 |
| URL 개인정보 | `google.com/url?q=` 래퍼를 풀어 호스트 이름만 남기고, 경로·쿼리·프래그먼트와 페이지 제목은 파싱 단계에서 버린다 |
| 기존 서비스와 중복 | 실제 주소가 `google.*/search`, `youtube.com/watch`, `youtube.com/results`인 방문은 제외한다. 이미 search·yt 서비스로 집계되기 때문이다 |
| 새로고침 | `page_transition`이 RELOAD인 기록은 제외한다 (BrowserHistory만) |
| 내부·로컬 주소 | `chrome://`, `chrome-extension://`, `file://`, `about:`, localhost, 사설 IP(10.x, 172.16~31.x, 192.168.x)는 제외한다 |
| URL 없는 기록 | "Chrome을 사용함"처럼 URL이 없는 기록은 제외한다 |
| 짧은 반복 방문 | 같은 도메인을 직전 방문 후 1분 안에 다시 방문한 기록은 1건으로 묶는다(연속 탐색은 하나로 이어 묶음). 한 사이트 안에서 페이지를 많이 이동하면 과대 집계되기 때문이다 |
| 사용자 제외 목록 | 사용자가 지정한 도메인(하위 도메인 포함)은 분석에서 뺀다 |
| 소스 중복 | BrowserHistory가 있으면 내 활동 > Chrome 레코드는 쓰지 않는다 |
| 보관 기간 | 웹 방문 데이터가 100일 미만이면 "보조 분석"으로 표시하고, 주 시계열(검색·YouTube)과 따로 해석한다 |

### 4.5 다중 채널(브랜드 계정) 분석 설계
| 항목 | 내용 |
|------|------|
| 전제 | YouTube 채널 1개 = Google 계정(개인 또는 브랜드) 1개. 시청·검색 기록은 채널마다 따로 쌓인다 |
| 한계 | 레코드에 시청 주체 정보가 없으므로 내보내기 단위로 프로필을 구분한다. 한 채널 안에서 여러 사람이 공유해 쓴 기록은 나눌 수 없다 |
| 식별 순서 | ① `channel.csv`의 채널 ID·채널명 → ② zip 파일명 → ③ 사용자 직접 입력 |
| 분석 모드 | **개별**: 프로필 하나만 필터링 / **비교**: 프로필별 라인·히트맵을 나란히 표시 / **통합**: 모든 프로필 합산 |
| 비교 지표 | 프로필별 일 평균 시청 수, 요일×시간 분포, 상위 콘텐츠 채널, 프로필 간 콘텐츠 채널 겹침 비율(Jaccard) |
| 검색 기록 | Google 검색 기록은 개인 계정에만 있으므로 프로필 필터를 적용하지 않는다. YouTube 검색 기록은 프로필별로 나눈다 |
| Chrome 기록 | 개인 계정에만 있다. 프로필 필터를 적용하지 않는다 |

> `channel.csv`의 실제 파일 이름과 컬럼 구성은 M1 단계에서 받은 데이터로 확인한다.

### 8.4 개발 환경 설정
모든 작업은 `M1-1/` 폴더에서 가상환경을 활성화한 상태로 진행한다.

**1) 가상환경 생성 (최초 1회)**
```bash
python -m venv .venv
```

**2) 활성화**
| 셸 | 명령 |
|----|------|
| Git Bash (Windows) | `source .venv/Scripts/activate` |
| macOS / Linux | `source .venv/bin/activate` |
| cmd | `.venv\Scripts\activate.bat` |
| PowerShell | `.venv\Scripts\Activate.ps1` |

> PowerShell에서 실행 정책 오류가 나면 해당 세션에서만 `Set-ExecutionPolicy -Scope Process RemoteSigned`로 허용한다.

**3) 패키지 설치**
```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

**4) 실행**
```bash
streamlit run app.py
```
> 노트북 실행: VS Code에서는 커널 선택에서 `.venv` 인터프리터를 고른다. 그 밖에는 `.venv`를 활성화한 상태에서 `jupyter lab`으로 실행한다.
> 전역 Jupyter로 열면 전역 Python이 쓰여 패키지를 찾지 못하므로 사용하지 않는다. (별도 커널 등록은 하지 않는다)

**5) 의존성 변경 시**
```bash
pip freeze > requirements.txt
```
> 실제로는 직접 쓰는 패키지만 버전을 고정해 관리하고, `pip freeze` 결과와 비교해 확인한다.

**6) 비활성화**: `deactivate`

| 여러 기기·사람이 한 계정 공유 | 노이즈 | 한계점에 기술 |

| 브랜드 계정 내보내기를 빠뜨림 | 해당 채널 분석에서 누락 | README 체크리스트, 개요 탭에 프로필 목록 표시 |
| 가상환경 미활성화 상태로 실행 | 패키지 버전 불일치 | README 첫 단계에 활성화 명시, 노트북은 `.venv` 인터프리터로 실행 |
| 개인정보 노출 | 프라이버시 침해 | NFR-01~03 |
| Chrome 기록 설정이 꺼져 있던 기간 | 웹 방문 데이터가 드문드문함 | 기록 중단 구간으로 표시, 꾸준히 쌓인 구간 위주로 해석 |
| 방문 횟수 ≠ 사용 시간 | 해석 왜곡 | "방문 이벤트 수" 기준이라는 점을 한계로 명시 |
