## 1. 시계열 분해 (STL)

| 항목 | 계획 |
|------|------|
| 목적 | 일별 건수를 추세·주간 계절성·잔차로 나눠, "요일 패턴을 걷어 낸 실제 흐름"과 "요일 패턴이 얼마나 강한지"를 본다 |
| 방법 | statsmodels `STL(period=7, robust=True)`. robust 옵션으로 몰아보기 같은 이상치의 영향을 줄인다 |
| 지표 | 계절성 강도 `max(0, 1 − Var(잔차) / Var(계절+잔차))`. 0이면 요일 패턴 없음, 1에 가까울수록 뚜렷함 |
| 대상 기간 | 웹 방문: **2026-04-01 이후** (그 전은 기록 중단 구간이 많아 분해가 왜곡됨, REPORT 인사이트 1) / YouTube 시청: 전체 기간 |
| 산출물 | `src/forecast.py`의 `stl_decompose()`, 이미지 `images/10_stl_decomposition.png` (원계열·추세·계절·잔차 4단) |
| 확인할 질문 | 웹 방문의 주간 패턴(평일 > 주말)이 YouTube보다 강한가? 생활 단계 경계에서 추세가 꺾이는가? |

## 2. 베이스라인 예측

| 항목 | 계획 |
|------|------|
| 방법 | ① Naive (마지막 값 유지) ② Seasonal Naive (7일 전 같은 요일 값) ③ 이동평균 (최근 7일 평균) ④ Drift (최근 기울기 연장) |
| 평가 | 마지막 14일을 떼어 둔(홀드아웃) 뒤 그 앞 데이터로 예측하고, 실제 값과의 **MAE**로 비교한다 |
| 예측 | 전체 데이터로 앞으로 14일을 예측해 방법별로 함께 그린다 |
| 산출물 | `baseline_forecast()`, 이미지 `images/11_baseline_forecast.png`, 방법별 MAE 표 |
| 초점 | project.md 요구대로 **정확도보다 가정과 한계 설명**에 집중한다 |

**리포트에 쓸 가정과 한계 (예정)**
- 과거의 요일 패턴과 수준이 앞으로도 이어진다고 가정한다. 생활 단계가 바뀌면(예: 과정 종료, 취업) 이 가정이 바로 깨진다.
- 외부 요인(일정, 휴일, 과제 마감)을 반영하지 않는다.
- 14일 홀드아웃 한 번의 결과라 우연에 따라 순위가 바뀔 수 있다. 여유가 되면 여러 구간으로 반복 평가(rolling origin)한다.

## 참고: 배포 없이 보너스를 제출하는 방법

project.md의 서비스화 보너스는 아래 중 하나를 고르면 된다. 배포를 하지 않는 경우 2·3번으로 제출할 수 있다.
1. 배포 URL 1개
2. 로컬 실행 화면 녹화(또는 시연 영상) + 실행 방법 문서
3. 대시보드 스크린샷 세트 + 필터·기간 변경 시나리오 설명

- 2·3번에 쓸 실행 방법은 `streamlit run app.py`이다.
- 스크린샷은 사이드바의 "이름 가리기"를 켜고 찍는다.
